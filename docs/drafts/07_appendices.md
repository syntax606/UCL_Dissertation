# Appendix A. Annotation codebook and annotator instructions

Source: `src/codebook.json` (scheme version 1.0). Counts from
`data/annotations/annotation_sheet_labeled.csv`.

## A.1 Structure of the scheme

Labelling is two-tier. The annotator makes one judgement about pragmatic function and one
independent judgement about vocal energy, and stance is derived from the first.

**Tier 1.** A single fine pragmatic-function tag from the fourteen in A.2, chosen from the subset
licensed by the target phrase's family.

**Tier 2.** Three fields. **Stance** is derived automatically from the Tier 1 tag and may be
overridden by the annotator. **Arousal** is an independent judgement of vocal energy, low or high,
made without reference to the function tag, so that the two axes can be crossed in analysis.
**Literal or non-literal** is derived from the tag and not annotated directly.

Every clip additionally carries a **confidence** value of clear or borderline, and an optional
**secondary function** where a clip plausibly supports two readings.

Annotating arousal separately rather than folding it into a single intensity scale is what makes the
matched-arousal control in [4.4] possible. A single scale would have made stance and energy
inseparable by construction.

## A.3 Phrase families

Families restrict which tags an annotator may choose, which reduces the decision space and keeps
tagging consistent across phrases that behave alike.

| Family | Phrases |
|---|---|
| agreement | `yeah`, `right`, `sure`, `okay`, `oh_yeah`, `oh_right`, `oh_sure`, `oh_okay`, `yeah_right`, `yeah_sure` |
| evaluative | `great`, `fine`, `oh_great` |
| challenge | `really`, `come_on`, `oh_really`, `oh_come_on` |

Seventeen phrase keys were defined. Eight carry enough labelled data to support the per-phrase
analysis and are the eight reported throughout [3.2].

## A.4 Discard reasons

A clip is discarded rather than labelled when any of the following applies. Discarded clips carry
the reason and are excluded from all analyses.

Noise, music or advertisement. Overlapping speech. Mistranscribed or not audible. Not the target use
of the word. Too ambiguous to label.

## A.5 Annotation protocol as implemented

There is no separate written instruction sheet for the main labelling pass. The protocol is embodied
in the annotation instrument, a self-contained offline HTML tool generated by
`src/07_build_offline_annotator.py`, and this section describes the constraints that instrument
imposed rather than quoting a brief that does not exist. The main pass was performed by the author.
The two auxiliary annotators in Appendix D worked from separate packages that carried their own
on-screen condition, and their task was the three-way stance call alone.

Each clip is presented individually with its audio embedded in the page, so labelling requires no
network access and no access to the corpus. The tool enforces an order. The Tier 1 function tag is
selected first, from the subset of the fourteen licensed by that phrase's family. Stance is then
derived from the tag and displayed, with an explicit override control so a departure from the mapping
is a deliberate act rather than a default. Arousal appears in a separate card, labelled independent,
and is not conditioned on the function tag. Confidence follows, as clear or borderline. A secondary
function and free-text notes are optional and collapsed by default.

Discarding requires selecting a reason from the fixed list in A.4 and cannot be done without one.

Two properties of this design matter for the analyses. Placing arousal on a separate card, after the
function tag but not derived from it, is the procedural counterpart of treating the two axes as
independent, which is what the matched-arousal control in [4.4] requires. And deriving stance from
the tag rather than asking for it directly means the three-way label inherits the consistency of the
fourteen-way scheme instead of being a fresh judgement per clip. Nine of the 873 kept clips are
marked borderline.

# Appendix B. Probe hyperparameters, dimensionalities and counts

Sources: `src/17_extract_features.py`, `src/18_probe.py`, `src/22_nonlinear_probe.py`.

## B.1 Probe and cross-validation

| Setting | Value |
|---|---|
| Classifier | L2-regularised multinomial logistic regression |
| Regularisation | `C = 1.0` |
| Solver iterations | `max_iter = 3000` |
| Class weighting | `balanced` |
| Standardisation | Per-feature, fitted within each training fold |
| Cross-validation | `GroupKFold`, grouped by `episode_id` |
| Folds | 5, reduced automatically to `min(5, n_groups, smallest class count)` |
| Prediction | Out-of-fold, `cross_val_predict` |
| Metric | Macro-F1 over the three stance classes |
| Random seed | 42 |

Grouping by episode rather than by clip prevents leakage through shared speaker, topic and recording
conditions. The speaker control in [4.4] regroups by show and is reported separately.

## B.2 Uncertainty and significance

| Procedure | Setting |
|---|---|
| Confidence interval | Episode-cluster bootstrap, whole episodes resampled with replacement |
| Bootstrap replicates | 1,000 |
| Interval | 2.5th and 97.5th percentiles |
| Null distribution | Empirical permutation null, full pipeline refit on shuffled labels |
| Permutations | 200 for the linear probe, 30 for the non-linear probe |
| p-value | `(count(null >= observed) + 1) / (n_permutations + 1)` |

The permutation null rather than the majority-class score is the reference throughout, for the
reasons in [3.6]. The majority-class figure of 0.196 is reported alongside for completeness only.

## B.3 Non-linear probe

Primary configuration.

| Setting | Value |
|---|---|
| Architecture | Single hidden layer, 64 units |
| Weight decay | `alpha = 1.0` |
| Early stopping | Enabled, 15 per cent validation fraction, patience 20 |
| Maximum iterations | 2,000 |
| Features and folds | Identical to the linear probe |
| Random seed | 42 |

The network is deliberately small and strongly regularised. A sufficiently large probe can learn the
task from almost any representation and thereby report on its own capacity rather than on the
encoding, so this rules out modest non-linear encoding rather than any conceivable encoding [Ch.6].

The gain over a linear probe is sensitive to this choice, moving by up to 0.06 across reasonable
settings, with some per-representation gains changing sign. The comparison is therefore run under six
configurations and the quantity carried into the chapters is the bound across all of them rather than
the ordering at any one.

| `h32/a1.0` | 32 | 1.0 | yes |

| `h64/a1.0/noES` | 64 | 1.0 | no |

remains the reference for absolute figures and this appendix is the reference for gains, which is why
[4.4] is written in terms of gains throughout.

## B.4 Feature dimensionalities

Measured from the stored arrays rather than restated from the extraction code. Every array carries
873 rows. The per-probe dimension is what a single probe actually receives.

| Representation | Stored shape | Per-probe dimension | Construction |
|---|---|---:|---|
| WavLM-large | (873, 25, 2048) | 2,048 | Mean and standard deviation over frames, per layer, 25 layers retained |
| HuBERT-large | (873, 25, 2048) | 2,048 | As WavLM |
| Whisper-small encoder | (873, 13, 1536) | 1,536 | As above, valid frames only, 13 layers |
| Mimi, deployed histogram | (873, 16384) | 16,384 | Eight codebooks, normalised unigram histogram over 2,048 bins each |
| Mimi, pre-quantisation | (873, 1024) | 1,024 | Projected encoder latent, mean and standard deviation pooled |
| Mimi, post-quantisation | (873, 1024) | 1,024 | Summed codebook vectors before output projection, pooled identically |

Two consequences are relied on in the chapters. WavLM contributes twice Mimi's pooled width, which
is why the 0.112 attributed to the codec encoder is reported as an upper bound [Ch.6]. And the two
sides of each ladder rung share a dimension exactly, 1,024 against 1,024 for Mimi and 2,048 against
2,048 for the Descript codec, which is why the quantisation estimate does not carry that caveat.

# Appendix D. Premise-check design

Sources: `src/14_build_premise_check.py`, `src/15_score_premise.py`, `src/16_premise_targetonly.py`.

## D.1 Purpose

The study rests on a premise that human listeners recover stance from delivery that the transcript
does not convey. If that premise fails, the probing results have nothing to be about. The check was
therefore run as a go/no-go gate before any GPU time was spent, with the decision rule fixed in
advance [3.4].

## D.2 Construction

Approximately 60 kept clips were sampled, balanced across stance and spread across phrases, with
every clip drawn from a distinct episode. The sample was split into Set X and Set Y and issued to two
auxiliary annotators in counterbalanced conditions.

| | Set X | Set Y |
|---|---|---|
| Annotator 1 | transcript only | audio with transcript |
| Annotator 2 | audio with transcript | transcript only |

Every clip therefore receives one transcript-only judgement and one audio judgement, from different
people, and neither condition is tied to a single annotator. Each package is a self-contained HTML
file with audio embedded directly, so annotators need no software and no access to the corpus.

Annotators make a three-way stance call with an explicit unsure option. The study's own stance labels
are the hidden reference and are written to `data/annotations/premise_key.csv`, which is not
distributed with the packages and is excluded from the repository.

## D.3 Decision rule, fixed before scoring

| Outcome | Reading |
|---|---|
| Audio agrees well and transcript-only is near chance | Contrast is speech-borne. Proceed. |
| Both agree well | Meaning is text-recoverable. Revise the framing before proceeding. |
| Audio does not agree well | Labels or contrast are weak. Investigate before spending compute. |

## D.4 Outcome

The second row obtained. Transcript with discourse context reached 0.65 accuracy against the hidden
reference and audio with transcript reached 0.73, against a three-way chance level of 0.33 [4.1].
Audio adds a real increment over the words, and discourse context recovers a substantial part of the
contrast on its own.

The framing was revised accordingly, as the rule required. The quantity of interest throughout the
dissertation is what audio adds over text rather than whether text fails, and the text baseline is
reported as a substantive competitor rather than as a floor. Reporting both conditions separately
also motivates the distinction between the target-only and discourse-context text embeddings in
[3.5].

Scoring reports accuracy against the reference, Cohen's kappa and the unsure rate per condition.
